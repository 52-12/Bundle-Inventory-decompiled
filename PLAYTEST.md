# Playtest guide

Everything here is prepared by `tools/make-playtest-worlds.ps1` and
`tools/install-playtest-mods.ps1`.

## What is installed

- **31 Prism instances**, grouped as *Bundle Inventory*: 9 Fabric, 9 NeoForge,
  9 Forge, 3 NilLoader, plus a Quilt check instance.
- Every instance has a world `BundlePlaytest`:
  - creative, peaceful, superflat (bedrock + 2 dirt + grass), no structures,
  - frozen noon, clear weather, no mob spawning (`bi:load` datapack),
  - cheats enabled (so `/function bi:kit` works),
  - save format generated by that era's own dedicated server.
- A datapack gives a **playtest kit once per world** (chat lists it; the chat
  prompt is clickable). `/function bi:kit` gives another copy at any time.
- Every instance's `options.txt` has GUI scale 2, Quake Pro FOV (`fov:1.0`), music volume 0, and `pauseOnLostFocus:false`.
- Fabric instances additionally have **Fabric API + Mod Menu + Cloth Config**
  so the config screen can be tested. The Quilt instance intentionally has
  only the mod jar. NeoForge/Forge/Nil have no config screen (defaults), as the
  mod's Cloth integration is Fabric-only.

## Launching

Prism is configured with `JoinServerOnLaunch=true` and
`JoinWorldOnLaunch=BundlePlaytest`, **inside `[General]`** (Prism ignores
settings placed under `[UI]`, which it appends to `instance.cfg`), so pressing
Play goes straight into the world and skips the main menu (verified on
1.21.5). If an instance ever lands on the title screen, close Prism and rerun
`tools/make-playtest-worlds.ps1 -Only '<instance name>'`.

## Checklist

Repeat for each instance in the priority table.

1. **Open** — hold a bundle, right-click. The bundle screen must render fully
   (plate, slots, scroller, fullness bar) with no purple/black squares.
   On Forge/NeoForge this is also the `pack.mcmeta` check.
2. **Insert** — pick up a loose stack (dirt/cobblestone/pearls/torches) and
   click it onto the bundle; shift-click another stack in.
3. **Remove** — right-click slots inside the bundle; hover a slot and press the
   drop key.
4. **Scroll** — open hotbar 6 (60 stacks). Mouse-wheel and drag the scroller;
   it should have multiple rows. (At 8 visible rows there are no hidden rows:
   `64 / 8 = 8`, so scrolling only exists with rows ≤ 7.)
5. **Fullness bar** — compare hotbar 1/2/3/4. Colour goes green → yellow →
   red. Inserting into hotbar 3 (full) plays the insert-fail sound.
6. **Bundle in bundle** — put the spare empty bundle into another bundle, then
   take it out. Hotbar 5 already contains a nested bundle.
7. **Open indicator** — open a bundle from the inventory grid; the opened
   bundle should render differently/highlighted.
8. **Creative shift-right-click** — in the creative inventory, shift-right-click
   a bundle **in your own inventory** once on the *Survival Inventory* tab and
   once on another tab (e.g. Building Blocks). It must open the bundle and the
   bundle must survive. This is the bug fixed in `e0dbd4e`; if it deletes the
   bundle on a non-Survival tab, report it with the instance name.
9. **Rejection** — try to insert the shulker box; bundles must refuse it
   (fail sound, no item moved).
10. **Config (Fabric only)** — Mod Menu → Bundle Inventory → config screen.
    Change visible rows (3–8), sounds, open-bundle highlight, equipment
    slots, and **fullness bar style** (boss bar, the default, or the smooth
    bar). Reopen a bundle and verify the change. Keep rows ≤ 7 if you still
    want to test scrolling. NeoForge/Forge/Nil use the built-in defaults
    (boss bar, 6 rows, sounds on).
11. **Persistence** — quit to title, rejoin the world, verify bundle contents
    and config survive.
12. **Log** — no `bundleinventory` exception, no `Failed to load function`, no
    missing-texture warnings. The kit functions (`bi:kit`, `bi:tick`,
    `bi:load`) must load silently.

## Pass/fail

A run is clean when:

- no crash on open/insert/remove/scroll/creative use,
- screen art renders (no black screen, no magenta bar),
- the fullness bar and sounds behave as above,
- the creative shift-right-click never deletes the bundle,
- no `bundleinventory` exception appears in the log.

Report a failure with: instance name, action, expected vs actual, and the
`latest.log` lines around the problem.

## Resetting

- Refill items at any time: `/function bi:kit` (or click `[refill kit]` in chat).
- Fresh world: delete `saves/BundlePlaytest` in the instance, then rerun
  `tools/make-playtest-worlds.ps1 -Only '<instance name>'`.
- Regenerate everything: `tools/make-playtest-worlds.ps1` (validates each
  datapack with that era's server before copying), then
  `tools/sync-prism-instances.ps1` after rebuilding jars.
